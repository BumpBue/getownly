# การตรวจ Responsive (ทก.01 ข้อ 2.3.4)

สคริปต์นี้เปิดเบราว์เซอร์จริงไล่ดูทุกหน้าหลักของทั้งสามบทบาท ที่ความกว้าง **375 / 768 / 1440 px**
รวม **84 หน้าจอ** แล้วรายงานว่าหน้าไหนใช้งานไม่ได้

มีไว้เพื่อให้ข้อ 2.3.4 เป็นสิ่งที่**รันซ้ำเมื่อไรก็ได้** ไม่ใช่ผลที่พิสูจน์ครั้งเดียวแล้วหายไป
ทุกครั้งที่แก้หน้าจอหรือเพิ่มคอลัมน์ในตาราง ควรรันซ้ำก่อน commit

## วิธีรัน

**ต้องมีสองอย่างรันอยู่ก่อน** เพราะสคริปต์นี้เข้าเว็บจริง ไม่ได้จำลอง

```bash
# เทอร์มินัลที่ 1 — ฐานข้อมูลและบริการเบื้องหลัง
pnpm docker:up

# เทอร์มินัลที่ 2 — ต้องมีข้อมูลตัวอย่างในฐานข้อมูล ไม่งั้นหลายหน้าจะว่างเปล่า
pnpm db:seed
pnpm dev

# เทอร์มินัลที่ 3 — รันการตรวจ
pnpm test:responsive
```

เก็บภาพหน้าจอไว้ดูด้วย (ลงที่ `frontend/test/responsive-output/`):

```bash
pnpm test:responsive -- --screenshots
```

## ⚠️ ห้ามรัน `pnpm build` ขณะที่ `pnpm dev` ทำงานอยู่

ทั้งสองคำสั่งเขียนลงโฟลเดอร์ `frontend/.next` ที่เดียวกัน
ถ้ารันพร้อมกัน แคชจะเสียหายและ**ทุกหน้าจะขึ้น error 500** พร้อมข้อความประมาณ

```
ENOENT ... .next\server\chunks\ssr\[root-of-the-server]__xxxx.js
```

ซึ่งจะทำให้การตรวจรายงานว่าทุกหน้าไม่ผ่าน ทั้งที่หน้าจอไม่ได้มีปัญหาเลย

**วิธีแก้:** หยุด dev server → ลบโฟลเดอร์ `frontend/.next` → เริ่ม `pnpm dev` ใหม่

## เบราว์เซอร์ที่ใช้

สคริปต์ใช้ `playwright-core` ซึ่ง**ไม่ดาวน์โหลดเบราว์เซอร์เอง** แต่จะไปหาเบราว์เซอร์ที่เครื่องมีอยู่แล้ว
ตามลำดับนี้

1. ค่าใน `RESPONSIVE_BROWSER` ถ้ากำหนดไว้
2. Chromium ที่ Playwright เคยดาวน์โหลดไว้ (`%LOCALAPPDATA%\ms-playwright`)
3. Microsoft Edge (มีอยู่แล้วในทุกเครื่อง Windows)
4. Google Chrome
5. `chromium` หรือ `google-chrome` บน Linux

ถ้าหาไม่เจอเลย จะขึ้นข้อความบอกให้ระบุ path เอง:

```bash
RESPONSIVE_BROWSER="C:/Program Files/Google/Chrome/Application/chrome.exe" pnpm test:responsive
```

## เกณฑ์ที่ถือว่าไม่ผ่าน

| รหัส | ความหมาย |
|---|---|
| `OVERFLOW` | หน้ากว้างเกินจอ ต้องเลื่อนซ้ายขวาถึงจะเห็นครบ |
| `OFFSCREEN` | ปุ่มหรือลิงก์อยู่นอกพื้นที่ที่มองเห็น — อาการที่พบบ่อยที่สุดคือคอลัมน์ปุ่มสั่งการของตารางหลุดออกไป |
| `SMALL` | ปุ่มเตี้ยกว่า 36 px ที่จอ 375 px กดด้วยนิ้วยาก |
| `TABLE` | ตารางกว้างเกินจอโดยไม่มีตัวเลื่อนแนวนอนครอบ |

**`OVERFLOW`, `OFFSCREEN` และ `TABLE` ทำให้สคริปต์คืน exit code 1** ทั้งสามอย่างแปลว่ามีปุ่มที่กดไม่ถึงจริงๆ
ส่วน **`SMALL` ขึ้นเป็นคำเตือนแต่ไม่ทำให้ตก** เพราะเป็นเรื่องดุลยพินิจ —
ลิงก์ข้อความในหัวเรื่องย่อมเตี้ยกว่าปุ่มเสมอ ถ้าให้ตกด้วยสคริปต์จะแดงตลอดเวลาจนไม่มีใครสนใจ
แต่ยังพิมพ์ออกมาให้เห็นทุกครั้ง

จึงนำไปต่อกับ CI ได้ทันทีถ้าต้องการ

### สิ่งที่จงใจไม่นับว่าไม่ผ่าน

- ลิงก์ที่อยู่ในประโยค (เช่นลิงก์ในย่อหน้าหรือในเซลล์ตาราง) — เป็นสิ่งที่อ่าน ไม่ใช่ปุ่มที่กด
- ช่อง checkbox และ radio — มี label ของตัวเองให้กดอยู่แล้ว
- ลิงก์ใน header, sidebar และ footer — ซ้ำกันทุกหน้า ถ้ารายงานจะได้ผลเดียวกัน 84 ครั้ง
  (ถ้าส่วนพวกนี้มีปัญหาจริง จะโผล่มาเป็น `OVERFLOW` แทน)

ปรับเกณฑ์และรายการยกเว้นได้ที่ `responsive.config.mjs`
